Domenia 1.0 — coffre Windows facultatif

Le coffre conserve uniquement les identifiants explicitement mémorisés par
l’utilisateur. Il est désactivé par défaut. La base SQLite ne reçoit aucun mot
de passe ; elle peut conserver le nom du compte et la préférence d’usage.

Cycle d’utilisation
1. Présenter un choix de mémorisation, non coché initialement, pour le compte.
2. L’utilisateur saisit son secret et confirme manuellement son authentification.
3. Après réussite pour le domaine, le compte et l’usage exacts, appeler Save avec
   -Enabled -AuthenticationConfirmed. Un changement de choix pendant la requête
   ne doit pas mémoriser un compte différent de celui authentifié.
4. Lire avec Get uniquement lors de la demande explicite d’utiliser ce compte.
   Le résultat est un PSCredential, jamais un mot de passe en texte. Il n’établit
   aucune connexion, ne confirme pas sa validité et ne réarme pas le garde.
5. En cas de refus, appliquer le garde partagé de compte : aucune relecture du
   coffre, tentative automatique ou changement de protocole. Une correction
   manuelle et une nouvelle authentification autorisée sont nécessaires.
6. « Oublier » appelle Remove pour le domaine, l’usage et le nom exacts. Désactiver
   un choix de mémorisation ne doit pas laisser croire qu’une entrée a été
   supprimée : traiter explicitement la suppression et son résultat.
7. À la fin de vie du compte en mémoire, libérer son SecureString. Fermer une
   session ne supprime pas une entrée persistante déjà acceptée par l’utilisateur.

Périmètre et protection
- Credential Manager, CRED_TYPE_GENERIC, persistance locale au profil Windows
  (CRED_PERSIST_LOCAL_MACHINE=2), sans itinérance demandée.
- Clé opaque SHA-256 versionnée : domaine stable + usage + compte. Ni serveur AD
  précis, ni chemin de base. Chaque autorité reste distincte : un login nu, un UPN
  et DOMAINE\login ne sont pas assimilés sans preuve d’identité.
- Usages : Directory, Remote, Laps, BitLocker, AD:<opération> et
  RemoteLocal:<poste-en-minuscules>. Un compte local exige le poste exact.
- Identifiant : 256 caractères au plus ; secret : 2560 octets UTF-16 au plus.
- Le code ne matérialise pas le secret dans une chaîne ou un tableau d’octets
  managés. Les zones natives sont effacées avant libération, même en erreur.
- Le coffre protège le stockage par le profil Windows. Un programme exécuté sous
  ce même compte Windows peut accéder à ses identifiants génériques ; ce module
  ne protège pas contre une session Windows déjà compromise.
- Les erreurs exposent une opération et un code Windows, sans secret ni contenu
  natif. Une entrée absente retourne null ; les autres erreurs sont signalées.

Validation
Test-DomeniaCredentialVault.ps1 contrôle clés, limites, refus, absence d’action
quand désactivé et compilation. -NativeWindows ajoute un véritable aller-retour
dans le coffre courant avec identité fictive aléatoire, sans réseau, puis
suppression dans finally. Ce test natif doit être demandé sur une cible Windows ;
les tests synthétiques seuls ne prouvent pas le fonctionnement de CredWrite.
